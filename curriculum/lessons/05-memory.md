# Memory Without a Heap

Without a heap, every byte of your program lives in one of three places,
and the linker knows the size of two of them at build time:

```text
 Flash (read-only, non-volatile)        RAM (read-write, lost at reset)
 ┌──────────────────────────┐           ┌──────────────────────────┐ 0x2000_0000
 │ .vector_table            │           │ .data   initialised statics │◄─ copied from flash at boot
 │ .text    code            │           │ .bss    zeroed statics      │◄─ zeroed at boot
 │ .rodata  consts, strings,│           │ (.uninit, heap if any)      │
 │          immutable static│           │            ▲ free           │
 │ .data initial values  ───┼──copy──►  │            │                │
 └──────────────────────────┘           │ stack ▼ grows down          │ top of RAM
                                        └──────────────────────────┘
```

- **Statics** (`.data`/`.bss`/`.rodata`) have a fixed address for the whole run.
- **The stack** holds locals and call frames; its peak depth is what you must budget.
- **The heap**, if any, is just another region someone carved out (module 06).

## const vs static

```rust
const MAX_NODES: usize = 32;            // a value, inlined at every use; no address
static BANNER: &str = "ECU v1.2";      // one object at one address, lives forever
static CRC_TABLE: [u8; 256] = make_table(); // computed at compile time, stored in flash
```

| | `const` | `static` |
|---|---|---|
| storage | none: copied into each use | exactly one location |
| address | not stable (each use is a fresh temporary) | stable, `'static` |
| interior mutability | no | yes, via `Sync` types (atomics, Mutex…) |
| typical placement | immediates / `.rodata` copies | `.rodata` (immutable) or `.data`/`.bss` |

**`const fn`** runs at compile time when used in a `const`/`static` initialiser.
Loops, `match`, `if`, arrays and arithmetic all work, so lookup tables (CRC,
sine, gamma curves) can be generated by the compiler and placed in flash at
zero runtime cost:

```rust
const fn crc8_table(poly: u8) -> [u8; 256] {
    let mut table = [0u8; 256];
    let mut i = 0;
    while i < 256 {                    // `for` isn't allowed in const fn yet; `while` is
        let mut crc = i as u8;
        let mut bit = 0;
        while bit < 8 {
            crc = if crc & 0x80 != 0 { (crc << 1) ^ poly } else { crc << 1 };
            bit += 1;
        }
        table[i] = crc;
        i += 1;
    }
    table
}
static CRC8_TABLE: [u8; 256] = crc8_table(0x1D);
```

A `const` block forces compile-time evaluation anywhere: `const { assert!(N > 0) }`.

## Mutable global state

`static mut` exists, but every access is `unsafe`, and since edition 2024 you
**can't even create a reference** to one (`&COUNTER` is an error). The reason:
two `&mut` to the same static, from main code and an interrupt handler, is
undefined behaviour the compiler can't catch.

The safe options, in order of preference:

1. **Atomics**: `static COUNTER: AtomicU32 = AtomicU32::new(0);` and
   `COUNTER.fetch_add(1, Ordering::Relaxed)`. They're `Sync`, need no `unsafe`, and
   work from interrupts.
2. **A Mutex-like wrapper**: `critical_section::Mutex<RefCell<T>>`,
   `spin::Mutex<T>`, Embassy/RTIC primitives (module 07).
3. **Raw access with a written safety argument**, when you truly need it:

```rust
static mut DMA_BUF: [u8; 512] = [0; 512];

fn dma_buffer_ptr() -> *mut u8 {
    // No reference is created: `&raw mut` makes a raw pointer directly.
    (&raw mut DMA_BUF).cast::<u8>()
}
```

## MaybeUninit: storage before values

An array `[T; N]` must always contain N valid `T`s. A fixed-capacity vector
wants N *slots*, of which only `len` hold values. That's what
`core::mem::MaybeUninit<T>` is for: memory that may or may not hold an
initialised `T`.

```rust
use core::mem::MaybeUninit;

let mut slots: [MaybeUninit<String>; 4] = [const { MaybeUninit::uninit() }; 4];
slots[0].write(String::from("hi"));                   // initialise slot 0
let s: &String = unsafe { slots[0].assume_init_ref() }; // we know it's initialised
unsafe { slots[0].assume_init_drop() };               // drop it exactly once
```

The rules are simple to state and easy to break:

- reading (`assume_init_*`) a slot that wasn't written is **undefined behaviour**;
- `MaybeUninit` never drops its contents, so **you** must drop initialised slots
  (in your container's `Drop`) or they leak;
- dropping a slot twice is UB (double free, double drop).

A container built on `MaybeUninit` keeps an invariant like "slots `0..len`
are initialised, the rest are not", and every method preserves it. That one
sentence is the whole safety argument, and you'll write such a container in
`stackvec1`.

`[const { MaybeUninit::uninit() }; N]` uses an *inline const* (Rust 1.79) to
repeat a non-`Copy` value in an array initialiser.

## Drop, leaks and `mem::forget`

- `Drop::drop` runs when an owned value goes out of scope, exactly once.
- Leaking (never dropping) is *safe* in Rust: `mem::forget(x)`, cycles of `Rc`,
  `Box::leak`. Your unsafe code must stay sound even if a user forgets values.
- `mem::replace(&mut slot, new)` and `mem::take(&mut slot)` move values out of
  a `&mut` without leaving a hole: the workhorses of in-place containers.

## Fixed-capacity containers

The `heapless` crate provides `Vec<T, N>`, `String<N>`, `Deque<T, N>`,
`IndexMap`, `BinaryHeap` and lock-free queues with capacity in the type.
Their API mirrors std's, except that inserting can fail:

```rust
let mut v: heapless::Vec<u8, 8> = heapless::Vec::new();
v.push(1).unwrap();               // Err(1) if full: the value comes back to you
```

"Give the value back on failure" (`Result<(), T>`) is the idiom: the caller
decides whether to drop it, retry or report it.

Other staples you'll build:

- **ring buffers**: fixed array + head index + length, overwrite or reject when
  full, used for UART RX, sample histories and event logs;
- **object pools**: N slots plus a free list, O(1) allocate/free, handles
  instead of pointers. A *generation* counter in each handle catches use-after-free.

## Stack discipline

The stack is the one region whose size the linker can't check for you.

- Avoid recursion in firmware: its depth is data-dependent. (MISRA C Rule 17.2
  bans it.)
- Avoid large locals and large return values; pass `&mut` buffers.
- Measure: `-Z emit-stack-sizes` (nightly) and `cargo-call-stack` estimate
  worst-case depth statically; **stack painting** (fill with a pattern at boot,
  check the high-water mark later) measures it at runtime.
- On Cortex-M you can place the stack at the *bottom* of RAM (flip-link) so an
  overflow hits the end of RAM and faults immediately instead of corrupting
  `.bss`.

> **Toyota lens:** ISO 26262-6 lists "no dynamic objects or variables" and
> "limited use of pointers" among the recommended coding practices, and
> AUTOSAR Classic configures every buffer, queue and task stack statically at
> build time. The designs in this module (const tables in flash, statics with
> safe interior mutability, `MaybeUninit`-based containers, pools with generation
> handles) are how that configuration looks in Rust. *Freedom from
> interference* between software partitions also starts here: if each component
> owns its statics, an MPU can enforce the boundaries.
